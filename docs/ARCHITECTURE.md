# 架构说明

## 1. 总览

```text
React 19 + TypeScript (WebView2)
  │  typed IPC bridge (src/lib/api.ts)
  │  virtual list · filters · selection · task/log/update views
  ▼
Tauri 2 command layer (src-tauri)
  │  state · configuration · native dialogs · events · updater
  ▼
heartopia-photo-core (crates/photo-core, pure Rust)
  ├─ crypto: AES-256-CBC + PKCS7, signature-based output type
  ├─ dates: filename ID parser + mtime fallback
  ├─ scan: recursive, bounded, cancellable, reparse-safe
  ├─ paths: canonical containment and protected-root policy
  └─ batch: immutable snapshot, worker pool, atomic no-clobber output
```

前端不直接访问文件系统。所有路径、扫描、解密、导出和更新操作都通过 Tauri command 进入 Rust；前端只能拿到脱敏视图（目录 basename、相对路径、文件 ID）。

## 2. 分层职责

### 前端

- 目录配置、最近目录选择、自动探测入口。
- 列表、筛选、日期快捷项、多选状态。
- 虚拟滚动（`@tanstack/react-virtual`）与按需缩略图。
- 任务进度、取消、行状态、失败清单导出。
- 日志面板、更新状态与重启提示。

选择状态以稳定 ID 保存，不依赖当前列表索引。筛选变化只影响可见行，不清空选择。

### Tauri 命令层

- 持有应用状态：输入/输出目录、最近记录、筛选偏好、当前扫描/任务、缩略图缓存。
- 校验命令参数，拒绝越权路径。
- 将长任务放到后台线程；通过事件推送进度，命令本身快速返回。
- 统一日志脱敏、配置持久化、文件对话框、打开目录、更新器。
- 扫描或解密期间应先取消任务、等待清理后再关闭窗口；更新重启命令会拒绝仍在处理任务的状态。不能把强制终止进程当作正常取消。

### heartopia-photo-core

纯 Rust，无 Tauri 依赖，可独立单测和基准测试：

- **crypto**：原生 AES-256-CBC/PKCS7；校验块长度、填充、输出大小上限和图片签名（JPEG `FF D8 FF`，PNG `89 50 4E 47 0D 0A 1A 0A`）。
- **dates**：从文件名提取图片 ID，按 Windows FILETIME 换算时间；失败回退文件修改时间并标记来源。
- **scan**：只读遍历，过滤扩展名，跳过重解析点（symlink/junction），支持取消和错误计数。
- **paths**：规范化输入/输出，检查相等、嵌套、别名、受保护根目录；解析不存在的输出路径时以最近存在祖先为基准。
- **batch**：接收不可变扫描快照和 ID 列表，按并发上限执行，逐文件回调状态；单文件失败继续。

## 3. 数据流

### 扫描

1. 前端调用 `scan_photos`，立即得到 `scanId`。
2. Rust 在后台线程遍历目录，周期性发送 `scan-progress`（已扫描、已发现、错误数、是否完成/取消）。
3. 每个文件生成记录：稳定 ID、相对路径、目录、大小、扩展名、解析日期、日期来源、初始状态。
4. 完成后前端调用 `list_photos` 获取不可变列表；列表只保留相对路径和 ID。
5. 取消时保留已发现结果并标记 `cancelled`，不删除任何文件。

### 解密

1. 前端提交 ID 数组；Rust 用当前扫描快照解析真实路径，忽略前端传来的任何路径。
2. 校验输出目录仍满足安全约束，并在任务开始时锁定路径快照。
3. 工作池按并发数读取、解密、校验图片签名、写临时文件、刷盘、原子改名。
4. 每完成一个文件发送 `task-progress` 和行状态；失败记录原因代码。
5. 全部完成、取消或致命错误后发送 `done`，清理临时文件。

### 缩略图

- 前端只对进入视口的行请求缩略图。
- Rust 侧限制同时解码数量，按 ID 维护有界 LRU 缓存（160px 预览）。
- 返回 `data:image/jpeg;base64`，不返回源文件路径。
- 前端维护小型缓存和进行中 Promise 去重，避免快速滚动重复请求。

## 4. 安全不变量

1. **源目录只读**：扫描和读取均以只读方式打开；不存在写入、重命名或删除源文件的代码路径。
2. **输出隔离**：输出目录规范化后不得等于输入目录、不得位于输入目录内部；禁止写入游戏安装目录和 TapTap 目录。
3. **不覆盖**：默认跳过已存在目标；自动重命名使用原子“仅当不存在时创建”的语义，永不复用已有文件名。
4. **原子输出**：写入同目录临时文件，完成后改名；解码、写入、刷盘或改名失败均删除临时文件。
5. **不跟随重解析点**：扫描和输出路径检查拒绝 symlink、junction 及其他 reparse point，防止逃逸到源目录。
6. **路径不泄露**：事件、日志、错误和导出清单不包含完整用户目录；界面只显示 basename/相对路径。
7. **密钥不落盘**：构建时注入的 AES 材料不进入配置、日志、崩溃信息或 IPC。
8. **更新必须验签**：更新器使用编译进应用的公钥校验安装包，失败不影响当前版本。

> 固定对称密钥会随发布二进制分发，无法对本地逆向者保密。它用于兼容游戏文件格式；安全性依赖更新签名、路径隔离和最小权限，而不是密钥保密。

## 5. 并发、取消与可靠性

- 扫描由单独后台线程执行，前端主线程只处理事件和渲染。
- 解密工作池并发数限制为 1–8，默认取较低值；I/O 与 CPU 任务共用上限，避免机械硬盘抖动。
- 取消使用原子标志；工作线程在文件边界检查；正在写入的文件完成清理后退出。
- 单文件失败不传播到整批任务；仅当输出目录失效、状态损坏等全局错误才终止。
- 进度事件做节流（例如 100ms 或每 N 个文件），避免大量文件刷爆 IPC。
- 日志按大小轮转，写失败不影响主任务。

### 可变规模与资源控制

面向不同规模的本地图片库，不以某台机器的文件数、分辨率子集或总容量作为固定假设。扫描与解密在后台执行，限制并发和缓存，避免阻塞界面；实际耗时和资源占用与文件数量、图片大小、磁盘性能有关：

- 列表只保留元数据，前端虚拟滚动，不创建大量 DOM 节点。
- 缩略图按需加载，缓存有界；滚动离开后不保留无上限图片。
- 扫描结果在内存中为紧凑记录；避免为每个文件保存绝对路径副本。
- 解密逐文件流式/限长读取，避免一次性把整批图片载入内存。

## 6. 日期解析策略

文件名形如 `<photoId>_<w>_<h>.jpg`，`Limit` 还包含 `normal+<shortId>+<kind>+<photoId>[@variant].png_<w>_<h>.jpg`。解析器只从文件名提取 ID，不将宽高后缀视为实际图像尺寸；实际尺寸以解密后图像的解码结果为准。

早期资料曾猜测文件名前缀是 Snowflake；对真实 `Photo` 样本批次的实证推翻了该猜测。图片 ID 是 **Windows FILETIME**：自 1601-01-01 UTC 起的 100 纳秒计数。

换算：

```text
unix_ms = filetime / 10_000 - 11_644_473_600_000
```

真实 `Photo` 样本的对照验证支持该换算规则：文件名推算时间与文件修改时间相符，ID 差值与毫秒时间差的比例符合 FILETIME 的 100ns 单位。样本数量、容量、日期跨度和时间差统计只保留在私有验收记录中，不作为所有图片库的固定指标。解析器不得改用 Twitter/Snowflake 的默认 epoch。

解析器输出：

- `timestampMs`；
- `dateSource = filetime | modified`；
- 本地日期字符串（YYYY-MM-DD）。

超出合理范围（例如早于 2015 或晚于当前时间太多）的 ID 不使用，回退修改时间。`Limit` 等文件名变体若无法提取有效 FILETIME，同样回退。这样即使某类文件名变体无法解析，筛选仍然可用且来源可见。

## 7. 配置、日志与隐私

- 配置：`%APPDATA%\Airisua\HeartopiaPhotoTool\` 中的 JSON（由 `directories::ProjectDirs` 决定）；包含输入/输出目录、最近记录、筛选、并发、重名策略、更新偏好。
- 最近目录：保存不透明别名 + 真实路径；IPC 只返回别名和 basename。
- 日志：`%LOCALAPPDATA%\Airisua\HeartopiaPhotoTool\logs\`，按大小轮转；记录相对路径、原因代码和计数。日志目录与源目录、输出目录分离。
- 失败清单：CSV，相对路径 + 原因代码，不写绝对目录。
- 崩溃/错误：统一映射为稳定中文消息，不把底层路径或密钥拼进 UI。

## 8. 更新架构

- Tauri Updater 插件，端点指向 GitHub Releases 的 `latest.json`。
- 构建启用 `createUpdaterArtifacts`，Windows 产物为 NSIS `setup.exe` 及其 `.sig`。
- 启用 `plugins.updater.requireSignedVersion = true`：Tauri 会读取 `.sig` 的 trusted comment 中的 `version:`，与 `latest.json` 公告版本比较；这防止伪造“更高版本号”去安装旧的、仍有效签名的包。
- 应用内置更新公钥；下载后由更新器验签，再交给安装器。
- 安装模式 `passive`，安装完成由用户确认重启。
- 检查更新设置可关闭；离线、超时、404、签名失败都只更新状态，不阻塞主功能。
- 元数据检查与安装包下载使用独立超时：检查保持较短等待，安装包传输允许更长时间，避免大包在普通网速下被提前中断。
- 配置目录独立于安装目录，升级不会清除用户配置。

## 9. 安装与运行环境

- NSIS x64 安装包，默认当前用户安装（无需管理员），便于用户态更新。
- `webviewInstallMode = offlineInstaller`，安装包内置 WebView2 离线安装器；即使目标机没有网络也能补齐运行时。
- 应用本身离线运行；只有检查更新需要网络，且可关闭。
- 不依赖游戏进程、官方服务或开发环境。

- 前端：筛选与本地日期边界、跨筛选保留选择、全选/反选/筛选全选计数、虚拟列表、路径遮罩、事件竞态。
- 集成：真实 `ScreenCapture` 只读样本（不提交原图）、源文件哈希前后一致、输出可解码、配置重启保留、日志脱敏。
